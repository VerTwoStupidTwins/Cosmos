# Thoth: NixOS recovery and installation

This archive reconstructs the minimal, previously evaluated flake from the conversation. It is **not** an image of your old `/tmp/nixos-config`: the original `flake.lock` and generated `facter.json` were not uploaded and cannot be reconstructed byte-for-byte. Regenerate both on the target Dragonfly before building. The desktop (Niri, Waybar, Kitty, etc.), Secure Boot/Lanzaboote and Chromebook keyboard/audio adjustments are **not installed by this minimal flake**; add them after a successful first boot.

## Before anything

The last successful Disko log indicated that the NVMe had a 2 GiB EFI partition, an unlocked LUKS partition, a formatted Bcachefs filesystem, and all six filesystems mounted. After a reboot they may simply be unmounted. **Do not run `destroy,format,mount` or `format,mount` again if that filesystem still exists.** Those modes can destroy existing data.

Boot the NixOS installer; disable Secure Boot for the first unsigned systemd-boot install. Work as root. In fish:

```fish
set -gx NIX_CONFIG 'experimental-features = nix-command flakes'
```

In bash:

```bash
export NIX_CONFIG='experimental-features = nix-command flakes'
```

Unzip this archive into `/tmp/nixos-config`, and `cd /tmp/nixos-config`. If the directory is a Git repository, run `git add -A` before evaluating a flake; new files must be tracked or staged.

## 1. Inspect existing storage, **read-only**

```bash
lsblk -f /dev/nvme0n1
ls -l /dev/disk/by-id/nvme-SHGP31-500GM_FJB9N514511509A4V
findmnt -R /mnt || true
cryptsetup status cryptroot || true
```

If the LUKS partition exists but is locked, open it (no formatting):

```bash
cryptsetup open /dev/disk/by-partlabel/disk-main-cryptroot cryptroot
```

Then confirm the unlocked mapper has Bcachefs:

```bash
blkid /dev/mapper/cryptroot
```

If it reports `TYPE="bcachefs"`, use **mount-only** below. If it does not, **stop** and diagnose before attempting a format. If filesystems are already mounted correctly, skip to the Facter and flake steps.

## 2. Generate a fresh Facter report and lockfile

There is deliberately no fake `facter.json` in this archive.

```bash
mkdir -p hosts/thoth
nix run nixpkgs#nixos-facter -- -o hosts/thoth/facter.json
nix flake lock
nix eval --raw .#nixosConfigurations.thoth.config.networking.hostName
nix build --no-link .#nixosConfigurations.thoth.config.system.build.toplevel
```

If the `nixpkgs#nixos-facter` command is not available, `nix-shell -p nixos-facter --run 'nixos-facter -o hosts/thoth/facter.json'` is an alternative. Verify the report was generated on Thoth, not another computer.

The original lockfile was lost with the live session. This will select new revisions from the specified branches, except Disko which is pinned to the previously used commit. If the build fails, stop and resolve it before installation.

## 3. Mount an existing, formatted system WITHOUT formatting

If `/dev/mapper/cryptroot` already contains Bcachefs, mount using the matching Disko flake and **mount-only** mode:

```bash
nix run .#disko -- --mode mount --flake .#thoth
```

If this invocation fails because the flake does not expose `disko` as a runnable package, use:

```bash
nix run github:nix-community/disko/cedd626e11b635470fa6f9fdb8ad79b0075dd7f9 -- --mode mount --flake .#thoth
```

Do NOT use `format,mount` here. Check:

```bash
findmnt -R /mnt
lsblk -f /dev/nvme0n1
```

Expected mountpoints: `/mnt`, `/mnt/boot`, `/mnt/home`, `/mnt/nix`, `/mnt/games`, `/mnt/.snapshots`.

## 4. Install the minimal NixOS configuration

Copy the configuration into the mounted root, including its generated flake lock and facter report:

```bash
mkdir -p /mnt/etc/nixos
cp -a /tmp/nixos-config/. /mnt/etc/nixos/
nixos-install --flake /mnt/etc/nixos#thoth
```

After successful installation:

```bash
nixos-enter --root /mnt -c 'passwd twins'
nixos-enter --root /mnt -c 'passwd root'
```

Inspect `/mnt/boot` and `/mnt/etc/nixos` before reboot. The initial system uses standard systemd-boot; Lanzaboote and Secure Boot are follow-up steps. **Do not turn Secure Boot on until signed boot artifacts and keys are configured and verified.**

## Notes and limits

- `/dev/nvme0n1` is the **internal SSD**; `/dev/sda` was the Ventoy USB on the earlier installer session. Verify this again before any destructive operation.
- This flake includes no keyboard/audio scripts and no complete Wayland desktop yet. It is intentionally the same minimal boot-first strategy.
- The package set may differ from the previously successful build because the original flake.lock was not preserved. Bcachefs external module compatibility must be rebuilt and confirmed.
- `allowDiscards = true` was already chosen; periodic TRIM policy can be added after the first boot.
- The NixOS storage-mount UUID generated by Disko is deterministic from the configuration, but make sure the new flake resolves and the installed root mounts properly.
- Keep a safe copy of the archive and resulting locked repository off the internal NVMe.
